# Reproducibility plan

Rebuilding this repository's analysis as a Quarto project that anyone can clone
and render end to end.

Audit performed 2026-08-29 against commit `94718d8`, tagged `v0-preexisting`.
Local toolchain at that point: R 4.3.2, Quarto 1.6.40, DESeq2 1.42.1.

**Status:** phases 0-4 are complete and phase 5 is under way; the analysis has rendered and been checked on a clean machine (see the 2026-09-06 entry at the end).

---

## Why this exists

The gonad and liver differential-expression results in this repository are real,
but at the time of the audit **no notebook in it ran as written**. The upstream
half was a shell transcript bound to one machine; the downstream half assumed a
working directory it was never rendered from; three of the six notebooks were
copied wholesale from an unrelated oyster experiment; and nothing anywhere
pinned a package version.

Seventeen findings are recorded below, grouped by what they cost. `B*` stops a
re-run outright. `R*` lets a re-run finish and hand back something subtly
different from what the manuscript reports. `E*` is the environment and
repository hygiene that makes both likely.

## Decisions

These were open questions in the first draft. They are settled and the phases
below reflect them.

| # | Question | Decision |
|---|---|---|
| 1 | Finding R2: the outputs claim an `lfc = 1.5` filter that never ran. Apply the filter, or correct the labels? | **`padj < 0.05` only.** Delete the unused `lfc.cutoff` / `svalue.cutoff` variables and correct the misleading labels. Published DEG counts stay as they are. |
| 2 | Should `DESEQ_output/` stay in git? | **Yes, keep it tracked.** Results stay browsable on GitHub without cloning. Phase 2 must therefore reproduce them in place rather than into an ignored directory. |
| 3 | Is functional enrichment in scope, given the existing results came from the DAVID web tool? | **In scope, and DAVID is dropped.** Replace it with a fully scripted R workflow (see below — the annotation source turned out to be much better than expected). |
| 4 | What happened to the brain tissue that the upstream notebook processes but nothing consumes? | **Presume the data is missing.** Do not delete the brain branch; park it, clearly marked, and revisit if the FASTQs are located. |

### On decision 3 — the annotation source

The first draft assumed real enrichment meant building a sockeye GO annotation
from scratch via BLAST against SwissProt. It does not. NCBI publishes a GO
annotation file for this exact assembly:

```
https://ftp.ncbi.nlm.nih.gov/genomes/all/GCF/006/149/115/
  GCF_006149115.2_Oner_1.1/GCF_006149115.2_Oner_1.1_gene_ontology.gaf.gz
```

Verified 2026-08-29:

- 1.6 MB, GAF 2.2, generated by NCBI 2023-12-02, tied to `GCF_006149115.2` —
  the assembly this project already used.
- 155,362 annotations over 32,629 genes (42,524 C / 55,639 F / 57,199 P).
- Column 3 is the `LOC…` symbol, which matches our gene IDs **exactly**: all
  32,629 GAF genes are present in the count matrix, so 32,629 of 37,942 genes
  (86%) carry GO terms. 24 of the 31 significant liver DEGs are annotated.

So enrichment becomes one `download.file()` plus `goseq`, with gene lengths
derived from `sequences/GCF_006149115.2_Oner_1.1_mRNA.gff`, which is already in
the repository. No BLAST, no web tool, no manual step.

**KEGG — correction.** An earlier draft of this plan said there was no KEGG
organism for *Oncorhynchus nerka*. That was wrong. The check queried the KEGG
REST organism list, got an empty response, and misread "no data" as "no match".
KEGG carries sockeye as organism **`one`** (genome T07952, 37,942 proteins — the
same gene count as our matrix), and its gene identifiers are NCBI GeneIDs, which
join to our `LOC` ids directly. The giveaway was in the repository all along:
`DAVID_KEGG_pathway.txt` contains strings like `one04110:Cell cycle`.

Both KEGG REST responses are vendored next to the GAF, with their retrieval date
recorded in `tag-seq/genome/kegg_one_SOURCE.txt`. No ortholog transfer needed.

## Findings

### Blocking — nothing rendered

- **B1 — Three different working-directory assumptions, none declared.** The
  notebooks live in `tag-seq/code/`. The DESeq2 notebooks read `data/…` and
  write `DESEQ_output/…`, paths relative to `tag-seq/`, one level up.
  `3_generate_gene_tables-salmon.Rmd` reads `../DESEQ_output/…`, relative to
  `code/`. Nothing sets `knitr::opts_knit$set(root.dir=)`. These were run
  chunk-by-chunk with the console parked at `tag-seq/`; pressing Knit fails on
  the first read.
- **B2 — The gene-table notebook operates on objects that never exist.** It
  loads `liver` and `gonad`, then manipulates `control_ploidy`, `heat_ploidy`,
  `diploid_heat` and five more, all leftovers from an oyster ploidy x
  multistressor experiment. It reads the DESeq2 CSVs with `sep=" "` when
  notebook 2 wrote them with `sep=","`. Its final chunk does not parse:
  `geom_text_repel(` is never closed.
- **B3 — Both enrichment notebooks belong to a different experiment.** They read
  `gene_tables/filtered/HISAT2_multiqc_biplot/*.txt` and `blast/geneid2go.tab`,
  neither of which exists here, and pin their shell chunks to
  `engine.path="C:/Windows/System32/bash.exe"`.
- **B4 — The upstream notebook is a transcript of one session on one machine.**
  Absolute paths throughout (`/home/shared/8TB_HDD_02/mattgeorgephd/…`). Two
  steps say "I moved files" by hand. It carries an abandoned bowtie2 branch
  alongside the HISAT2 branch actually used, and a brain branch (decision 4).

### Silently wrong — runs, but may not reproduce

- **R1 — Sample labels are assigned by position, and the check is tautological.**
  `colnames(cts) <- row.names(trt_list)` overwrites `01B_S43_R1.gtf…` with
  `B01…` purely by column order. The next line tests
  `all(colnames(cts) %in% rownames(coldata))`, which is now unconditionally
  `TRUE`. The order is correct in the committed matrices (verified), but any
  re-run of `prepDE.py` that reorders columns mislabels every sample silently.
  **Highest-value fix in this plan.**
- **R2 — Reported thresholds do not match the filtering that ran.** See decision 1.
- **R3 — The reference level is implicit.** `lfcShrink(coef=2)` relies on
  `factor()` sorting `social` before `territorial`. Correct today; a renamed
  level silently flips the sign of every `log2FoldChange`.
- **R4 — Heatmap group colours are hardcoded counts.**
  `ColSideColors = c(rep("royalblue1", 15), rep("red3", 15))` in liver, `14`/`14`
  in gonad, both assuming column order rather than deriving it from `coldata`.
- **R8 — The gene-identifier step destroyed the identity of 4,731 genes.**
  *(found during phase 2, fully characterised and **fixed** afterwards)* Row names
  are `gene-<id>|<id>`, where the identifier is a `LOC` number for genes with no
  assigned symbol and a real symbol for the rest. The `.Rmd` split each name on
  the literal string `LOC` and kept the third piece, which works for
  `LOC115144855` and turns `gene-arhgap8|arhgap8` into the string `LOCNA` — for
  4,731 genes, 12.5% of the annotation, and disproportionately the
  well-characterised ones.

  My first assessment — that these were dropped before reaching any output — was
  wrong. `data.frame()` de-duplicates row names, so they reached the published
  tables as `LOCNA.1`, `LOCNA.2292` and so on: identifiers corresponding to
  nothing, joining to nothing. In the committed results that was 936 rows in
  `liver-ALL-DEG-apeglm.csv` and 3,141 in the gonad equivalent, including
  **3 of 31 significant liver genes and 309 of 1,630 significant gonad genes**,
  all of which the gene tables then discarded as "no description".

  See *Identifier repair* below.
- **R5 — Sample exclusion is a comment toggle with no recorded criterion.** Gonad
  drops `C05` and `C17`; liver has the same two lines commented out. The only
  justification in the repo is "MultiQC report: Pheatmap: C05, C17", with no
  MultiQC output committed to support it.
- **R6 — `cache = TRUE` paired with `rm(list=ls())`.** Cached chunks restore
  objects the clear was meant to remove, and the cache is not invalidated when
  `data/` changes.
- **R7 — `setwd()` inside chunks.** knitr resets the working directory at every
  chunk boundary, so this works interactively and quietly writes to the wrong
  place when rendered.

### Environment and repository

- **E1 — No versions pinned; missing packages failed open.** *(fixed in phase 1)*
- **E2 — Twelve of twenty-six loaded packages were never called.** *(fixed in phase 1)*
- **E3 — RStudio session state committed; no `.gitignore`.** *(fixed in phase 0)*
- **E4 — Inputs and derived outputs are mixed.** `DESEQ_output/` is 37 MB of
  regenerable results; `data/` and `genome/` are 79 MB of inputs. Per decision 2
  the results stay tracked, but source and derived should still be signposted.
- **E5 — The two DESeq2 notebooks are a copy-paste pair.** Normalised for tissue
  name, 571 and 582 lines differ in five places.
- **E6 — The README documents logistics, not the analysis.**
- **E7 — `sequences/GCF_006149115.2_Oner_1.1_mRNA.gff` is tracked and zero
  bytes.** *(new, found during phase 3)* The `sortBed` step in the upstream
  notebook that should have written it produced nothing that was committed. Gene
  lengths for `goseq` come from the assembly feature table instead. Phase 4
  should either regenerate the file or stop tracking it.

## Phases

### Phase 0 — Stop the bleeding &nbsp;`DONE` (commit `66ff8b6`)

Tagged `v0-preexisting` at `94718d8` first, so the outputs the manuscript cites
stay retrievable. Then removed 217 files of editor session state from the index
(`.Rproj.user/`, `.RData`, two `.Rhistory`), added a `.gitignore`, and set

### Phase 1 — Pin the environment &nbsp;`DONE` (commit `de3c217`)

`renv.lock` now records 148 packages against R 4.3.2 and Bioconductor 3.18,
including DESeq2 1.42.1, apeglm 1.24.0, PCAtools 2.14.0, ashr 2.2-63.

Pinning was not the formality it looked like:

- `renv::init()` defaults CRAN to `packagemanager.posit.co/cran/latest`. Against
  latest, `Deriv` 4.3.0 — pulled in transitively by
  `ggpubr -> rstatix -> car -> pbkrtest -> doBy` — fails to compile on R 4.3.2,
  because its sources now target R >= 4.5. A lockfile that cannot restore is not
  a pin. Fixed with a dated snapshot, `cran/2024-04-24`, contemporary with
  Bioconductor 3.18.
- The pin must be applied **after** `renv/activate.R`, which restores the
  lockfile's repositories and would otherwise overwrite it; and it must **amend**
  the `CRAN` entry rather than replace the vector, which silently drops all five
  Bioconductor repositories and makes DESeq2 unresolvable. Both are commented in
  `.Rprofile`.
- renv itself is pinned to 1.0.7, the version in that snapshot, so a clean clone
  can bootstrap from the same place.
- The library was rebuilt entirely from the pinned repositories rather than
  hydrated from the author's user library, which had produced a mixed set (a
  newer `ggpubr` demanding a `cowplot` the snapshot cannot supply).

Both DESeq2 notebooks now use explicit `library()` calls. Nothing installs at
render time, and a missing package stops the render — the old
`sapply(load.lib, require)` returned `FALSE` and carried on. Fifteen of the
twenty-six loaded packages were dropped after verifying none of their functions
are called.

`tag-seq/code/.renvignore` excludes the three oyster-project notebooks from
dependency discovery; `3_generate_gene_tables` additionally requests `kmisc`,
which is not a CRAN package and would fail every restore. Phase 3 removes that
exclusion for the rewritten file.

**Verified:** `renv::status()` reports a consistent project, all ten analysis
packages load from the project library, and the rewritten `load_libraries` chunk
executes without error.

### Phase 3 — Rebuild the gene tables, and script the enrichment &nbsp;`DONE`

- Rewrite `03-gene-tables.qmd` against the two tissues that exist. The
  characterized / uncharacterized / `LOCNA` split is about fifteen lines of

- Pass tibbles directly rather than round-tripping through CSV with mismatched
  delimiters.
- Delete `X_GOterm_Annotation.Rmd` and `X_GOSeq_annotation.Rmd`. *(B3)*
- New `04-enrichment.qmd`: download the assembly GAF, build the `gene2GO`
  mapping, compute gene lengths from
  `sequences/GCF_006149115.2_Oner_1.1_mRNA.gff`, and run `goseq` with the
  length-bias correction. Commit the GAF alongside the other inputs so the
  analysis does not depend on NCBI staying up. Report GO only; KEGG needs
  ortholog transfer and is out of scope.
- Drop the rewritten gene-table notebook from `.renvignore` so its dependencies

**Gene tables.** `03-gene-tables.qmd` replaces the 165-line oyster notebook.
Whatever produced the committed `gene_tables/` was never in the repository, so
the rule was reconstructed from the outputs and verified: drop genes with no
description (the old code's `LOCNA` class), then split the rest on whether the
description begins with `uncharacterized`. Reproduces exactly —
liver 28 / 0 / 28, gonad 1280 / 41 / 1321 — and `uncharacterized_stats.txt` is
byte-identical.

One deliberate format change: the committed tables were written with
`quote = FALSE, sep = ","` while descriptions contain commas
(`uncharacterized LOC115129809, transcript variant X3`). In
`gonad_characterized.txt` only 754 of 1,280 rows had the expected 8 fields; 526
had 9-11 and could not be read back. They are now properly quoted CSV. Rows and
values are unchanged. `gonad_all_LOCID.txt` also reorders 71 of 1,321 lines —
adjacent pairs with near-tied fold changes, swapped by apeglm's third-decimal
shift from phase 2. Same gene set.

**Enrichment.** `04-enrichment.qmd` runs `goseq` — with its length-bias
correction — for GO and KEGG, both tissues. Universe is every gene with an
adjusted p-value; DE is `padj < 0.05`, the same rule the results tables use.

Gene lengths could not come from `sequences/GCF_006149115.2_Oner_1.1_mRNA.gff`
as planned: **that file is tracked and zero bytes** (new finding E7). They come
from the assembly feature table instead — median mRNA interval length per gene,
keyed by `GeneID`, which is our `LOC` id without the prefix. 37,929 of 37,942
genes get a length.

Results, written to `tag-seq/GO_output/<tissue>/`:

| tissue | categories tested | FDR < 0.05 |
|---|---|---|
| liver GO | 3275 | 0 |
| liver KEGG | 187 | 0 |
| gonad GO | 5209 | 1 |
| gonad KEGG | 194 | 0 |

The single hit is `GO:0051131` *chaperone-mediated protein complex assembly*
(BP, 6 of 6 genes DE, FDR 0.028). Liver has only 31 significant genes, so no
enrichment there is the expected result rather than a failure.

**On the DAVID files.** They are not enrichment results and never were.
`DAVID_GOterms.txt` is a 53-row gene report (symbol, name, species) with no GO
terms in it at all, and `DAVID_KEGG_pathway.txt` is a 13-row gene report listing
each gene's pathways. There was no committed enrichment analysis to reproduce,
so these numbers are the project's first.

**Done:** `gene_tables/` and the enrichment results regenerate from a render, and
every notebook in the repository either runs or is gone.


### Phase 4 — Make the upstream steps honest &nbsp;`DONE`

### Identifier repair &nbsp;`DONE`

Fixes R8. Identifiers are now taken from after the pipe, which is unique across
all 37,942 genes. Descriptions and lengths come from the assembly feature table
instead of `Onerka_LOCID_gene_table.txt`, which is keyed entirely by `LOC`

verified, so this is a strict superset, not a different annotation. KEGG's
GeneID keys are mapped through the same table rather than by pasting a `LOC`

rest.

## Post-phase-4 audit (2026-08-30)

An independent audit re-checked the phase 0-4 claims by recomputing the
committed result tables rather than re-rendering. Everything checkable held:
zero fabricated `LOCNA.*` identifiers remain in any of the eight `ALL-DEG`
tables; missing descriptions are 11 of 5,646 (liver) and 12 of 18,935 (gonad);
the gene tables re-derive exactly from `*-SIG-DEG-apeglm.csv` (liver 31/0, gonad
1,587/41, 1,628 LOCIDs, identical gene sets); recomputed `padj < 0.05` counts
match the committed `*-gene-counts.csv` exactly; and all 32,629 genes in the
vendored GAF are present in the 37,942-gene count matrix.

It also found twelve open items. Three have been closed:

**Step 1 — one command means the whole analysis** *(B5, B6, E8)*

- `_quarto.yml` now declares an explicit `project.render` list. Without it,
  Quarto rendered every `.qmd` and `.Rmd` in the project, including the
  deprecated upstream transcript — ~40 `{bash}` chunks with no `eval` guard on
  any of them, pointing at `/home/shared/` and Gannet *(B5)*.
- That transcript moved to `archive/`, out of render scope, with a
  `knitr::opts_chunk$set(eval = FALSE)` guard added as a second line of defence.
- `render-all.sh` at the project root is now the documented entry point. A bare
  `quarto render` renders the parameterised notebook 02 once, with its default
  tissue, so it regenerated liver and silently left gonad alone *(B6)*. The
  script renders 02 per tissue via the existing
  `tag-seq/code/render-differential-expression.sh`, then 03, then 04, and prints
  the `git diff --stat` command that constitutes the reproduction check.
- `tag-seq.Rproj` moved to the project root as
  `project-sockeye-tagseq.Rproj`. In `tag-seq/` it set the interactive working
  directory one level below what `execute-dir: project` assumes, so every
  `source("tag-seq/code/_common.R")` failed when chunks were run by hand *(E8)*.
- README rewritten: `./render-all.sh` not `quarto render`, a table of what each
  notebook reads and writes, and the expected-diff statement.

**Step 4 — derived-file bookkeeping** *(E7, E11, E13)*

- `sequences/GCF_006149115.2_Oner_1.1_mRNA.gff` untracked. It was a zero-byte
  file asserting that a derived artefact existed; it is regenerated by the
  `bedtools` chunk in 01 on Raven, and nothing downstream reads it — goseq's
  lengths come from the feature table. Recorded in a new
  `tag-seq/sequences/README.md`, with the prose in `_common.R` and 04 corrected
  *(E7)*.
- The DAVID files moved from `tag-seq/DESEQ_output/gonad/` — where a render
  overwrites its neighbours — to `archive/david-2023/`, with `archive/README.md`
  stating why they are not maintained: they cannot be reproduced from this
  repository, and both are per-gene reports (columns: gene symbol, name,
  species, pathway) with no over-representation statistic and no FDR anywhere in
  either file *(E13)*.
- Signpost READMEs in `tag-seq/data/`, `tag-seq/genome/`, `tag-seq/sequences/`
  and `figures/` classify every tracked file as input, provenance-only or

**Step 5 — input integrity** *(E12, part of)*

- `CHECKSUMS.sha256` records sha256 for the eight files the analysis reads: both
  count matrices, both treatment tables, the feature table, the GAF, and the two
  vendored KEGG REST responses. Verified against the current working tree.
- `verify_inputs()` in `_common.R` checks the manifest whenever the file is
  sourced, i.e. at the top of 02, 03 and 04. A mismatch warns rather than stops —
  a deliberate data update should be loud, not blocking — and the check skips
  with a message if `digest` is unavailable, so no notebook gains a hard
  dependency. This is finding R1's failure mode one layer out: R1 was a count
  matrix whose columns had been silently reordered; this catches the input file
  changing at all.
- Still open under E12: `LICENSE` and `CITATION.cff`.

**Steps 6 and 7 — publish, and check it from outside** *(E6, P5)*

- `index.qmd` at the project root is the landing page: design, sample table,
  results as committed, links to the five rendered notebooks and the tracked
  result directories, and a data-availability statement. It carries the C05/C17
  caveat as a callout, because a reader who lands on the site should meet that
  before they read the gonad numbers.
- `output-dir: docs`, and `/docs/` is gitignored. Nothing generated is
  committed, so a stale rendered page cannot contradict the tracked tables. The
  Action publishes `docs/` to Pages as a build artifact instead, which needs
  Pages set to "GitHub Actions" as its source.
- `check-reproduction.R` replaces `git diff --exit-code` as the reproduction
  test. A bare diff cannot work here: re-rendered PNG bytes always differ, and
  apeglm's iterative shrinkage moves `log2FoldChange` in the third decimal
  across package versions — exactly the columns 02, 03 and 04 write. So images
  are reported and ignored, tables are compared on matched keys with a relative
  tolerance (1e-3, and 1e-2 for p-value columns, which span thirty orders of
  magnitude), and significance calls at 0.05 must be identical with no tolerance
  at all. Files it cannot parse count as failures, not passes.
- `.github/workflows/render.yml` restores `renv.lock` on a clean Ubuntu runner,
  verifies `CHECKSUMS.sha256`, runs `./render-all.sh`, then
  `check-reproduction.R`; it uploads the rendered site and, on failure, the
  result diff. First run builds the Bioconductor stack from source (budget an
  hour); later runs restore from cache.

`check-reproduction.R` was exercised against deliberately perturbed result
tables before being committed: fold changes moved 0.05% pass, 5% fail, a single
padj nudged across 0.05 fails on the significance call even though the numeric
move is 0.6%, a dropped gene fails on dimensions, and appended bytes in a PNG
pass as an ignored image. It and the `verify_inputs()` addition to `_common.R`
both parse under R 4.5.3.

## First clean-machine render (2026-09-06, PR #4)

Neither run of the render workflow on 2026-08-30 had got past its first step:
notebook 01 has only bash chunks, Quarto inferred the Jupyter engine, and the
runner had no `nbformat`. With `engine: knitr` declared, and the parameterised
02 renders named through `output-file` rather than `--output` (which Quarto
1.10 mishandled; CI now pins 1.6.40), the analysis rendered end to end on
Ubuntu for the first time.

**What reproduced.** Every DESeq2 table: same rows, same `padj < 0.05` calls in
both tissues. baseMean and normalised counts agree to 1e-14 relative; apeglm
`log2FoldChange` to 0.0008 and `lfcSE` to 0.0013 log2 units. Step 3 of the
post-phase-4 audit, "no independent re-render has been performed", is closed.

**What did not.** The gonad enrichment. Gene-to-category counts were identical,
but goseq's Wallenius p-values moved because the length-bias spline fitted by
`nullp()` is platform-sensitive, and the three enriched terms sat at the
threshold: FDR 0.004 / 0.039 / 0.045 on macOS, 0.060 / 0.057 / 0.081 on Linux.
Investigating why the weighting mattered so much showed that it should not have
been applied at all. TagSeq is 3′-end counting, so the length bias goseq
corrects for is not present by design, and the length association in these
data is strong and negative (gonad: 27% of the shortest-decile genes DE against
about 5% in every other decile). The test is now hypergeometric, exact and
deterministic. Gonad returns 35 GO terms and 6 KEGG pathways at FDR < 0.05,
ribosomal and mitochondrial; liver still none. The Wallenius tables are in the
history at `bf5bf06` and before.

**Checker.** Ten of the fourteen failures the run reported were the checker's:
a non-unique key on the single-gene-count tables, no absolute floor under the
relative tolerance, and 0.05 call checks on raw p-values. All three fixed and
verified against the Linux outputs and against perturbation probes.

Also closed from the earlier list: E12's `LICENSE` and `CITATION.cff` remain
open; the eleven count tables changed to comma-separated by `8ea8f80` but never
regenerated are now regenerated and committed; GitHub Pages is enabled with the
Actions source.

## How you will know it worked

   manual steps. This is the bar the repository failed at audit time.
2. **It renders the same.** Diff phase-2 outputs against `v0-preexisting`. Every
   difference should be one you can name and defend.
3. **It renders elsewhere.** The GitHub Action is the real test: a machine that
   has never seen this project, restoring from `renv.lock`, producing the same
